# Corpus audit, 2026-07-29

What is a source of truth, what was archived, and why. Written because the corpus had
grown three ways of holding the same fact and the copies had diverged — and because a
developer reading a stale conclusion during implementation is the most expensive kind of
error this project makes.

**The precedent, from the project's own record:** a claim that "FF16 has an open
dropped-derivative bug" survived across **four documents** after it had been fixed. A
design blocked on it would have been blocked on nothing.

## What was archived, and the specific hazard in each

All four are in [`archive/`](archive/) with a banner at the top of the file stating what
survives and what does not. Nothing was deleted.

### `archive/corner-and-envelope-result.md` — the reason this audit happened

Concludes that TF24's collar operating point is a corner "at every state that solves",
that this is "the ordinary case", and that an envelope-justified adjoint loses
**89–100%** of the carbon-channel derivative. Report 06 derives the entire reverse pass
*from* the envelope theorem, so on its face this kills the design.

It does not, and the document contains its own refutation. Every measurement is on a
**single soil layer at `test-leaf.r`'s parameters** — a configuration its §5 admits is
degenerate, with `soil_consumption_` at 1e-13 to 6e-11. There `p*` is pinned at
`bound_a`, the zero-uptake collar; §3's table shows the offset `p* − psi_soil` is
**0.004900 at every state**, exactly `grav_head_z_[0] = 9.8e-3 × 0.5`. It is a bound
pinning in a barely-transpiring leaf, not a feature of the objective.

On a production run: corner incidence **zero** in 10 153 records, minimum margin
**0.02688 MPa** (27× `GSS_tol_abs`) *growing* with dryness, and the operating point a
genuine stationary interior maximum with the envelope holding to **0.006–0.9%** on
`d(profit)/dψ`. The real defect is the co-output — `d(consumption)/dψ` off by
**47.6–53.2%** — which is report 06's subject.

**The general lesson, and the reason this is the lead item: a probe's configuration is
part of its result.** This document states that correctly in §5 and generalises from the
same probe in §1, §4 and §6.

## The rules that keep this from happening again

Three, each earned by a specific failure above.

**1. One home per fact, named before the code is written.** `build-plan.md` §4 assigns
every kind of statement a document, and two of its tasks are doc changes that must land
in the same PR as the code they describe. The corpus failed because a claim could live
in a report, a requirements list and a task list simultaneously, and only one of the
three got corrected.

**2. Provenance, unchanged from `v3-requirements.md` and the one thing worth keeping
from it.** A claim earns a place in a live document only on a passing test, a
re-runnable probe, or a code location read directly — **never on another document's
say-so.**

**3. A measurement carries its configuration.** Soil layer count, driver, tolerances,
lifetime, trait set. A conclusion drawn from a probe inherits the probe's degeneracies,
and the corner result is what that costs. The `scripts/` probes each state their
configuration in the header for this reason.
