## Triage: 3 — the System interface odelia offers plant, and the record every pass reads

A change to what a System declares and to what a row holds is read by four passes
(forward, pinned replay, walk, sweep) in two repositories. The requirements arrive
partly as mechanisms (R5 "one account", R4 "declare, don't handle"). No spike was

## The witnesses, read from the code

| # | Witness | Range of the state it divides | Origin | Where it lives today | What each later pass does |
|---|---|---|---|---|---|
| W1 | controller step end | whole state | chosen by error control | `SolverInternal::step`, `instruction{time, step_size}` | held (replay `step_by`, walk `advance_recorded`, sweep row by row) |
| W2 | scheduled time (introduction, harvest, pulse, extreme) | whole state, plus a map | known | plant `SCM::run_next` → `advance_adaptive` to `node_schedule.next().time`; `instruction{insertion}` row; `Patch::apply_insertion` | held; the map is applied (walk) and transposed (sweep, `solve_adjoint`) |

The concept all five are instances of: **a stop** — a time at which the integration
of some range of the state must end, either known before the step (W1–W3) or the
zero of a sign value (W4, W5). The word is already odelia's: `choose_substeps`
calls the knots it lands on `stops`, and round 4's R design defines the knots as
"stops of the integration that holds the soil".

What the witnesses differ in is two attributes, not five:
- *range* decides **which integrator lands on it**: the whole state's stops end a
  row (W1, W2, W5); a block's stops are landed by that block's own integrator
  inside the row (W3 by the soil's substeps, W4 by the node's pieces);
- *placement* decides **what a later pass does**: a row end is held by every pass
  after the forward, because a row is the sweep's unit and time does not cross
  rows; a located stop inside a row is located again by each pass at its own θ and
  moved by the implicit function in the sweep.

Three integrators remain, because they differ for reasons that are not about
stops: the row is error-controlled; the soil's substeps take their inputs on a line
under their own tolerance (stiffness); a node's pieces read the field sampled on the
step's dense output (cost: one node's rates, not the patch's). Merging those would
be a type whose fields only some instances use.

Rows are ordinary rows, so replays, walks and the sweep are untouched.

- R8: the node split is untouched ✓.

## The commitment

A stop's range decides where it lands. A stop whose range is the whole state ends a
row, and every pass after the forward holds it. A stop of a block is landed inside
the row by that block's integrator, placed again by each pass at its own θ and moved
in the sweep. The System declares each sign value's range once, beside the value.

Kept true by:
- *the declaration's type.* `sign_aux{aux, ends_step}` cannot name a sign value
  without its range. The Patch code that reads the list is generic over it, so no
  point has a code path of its own.
- *where the one call lives.* `step_end` is called only from
  `SolverInternal::step`. `step_by` and `step_to` (pinned replays and walks) and
  `step_adjoint` (the sweep) have no call to it, so no later pass can move a row
  end: the code to do so does not exist.

Check of the commitment:
- *True in the real environment:* dry, at 3e-4, measured end to end [m].
- *Breaking it is worse, not merely different:* a whole-state zero landed by a block
  integrator is the soil split, 0.010 against 0.006 [m], which fails R1. A row end
  moved in the sweep needs a time adjoint carried between rows, which no pass has.
- *Removes categories:* no per-point code in Patch, odelia or the passes; no second
  account of the knots.
- *Named kill:* R9 or R2's radius (below).

## Kill question

Assumption whose falsity makes this unnecessary: that a K point inside a step leaves
a first-order error in the gradient which the forward's error control does not see
and cannot buy back within R3.

Verdict: survives. The ledger shows the error: 0.048 against the 0.006 bar [m]. It
shows the error control cannot buy it back: the tolerance ×0.1 within 15 d of
closing edges reached 0.025 at +8.6% rows [m], and ×0.1 everywhere costs far more
than 14%. And it shows the error is the switch's: part 4's H2 reproduced −0.173ε of
the −0.176ε move from the switch steps' total sensitivity [m].

## Consistency pass

- *R3, rows against time.* Rows +12.8% [m] meet the bar. Time, by the brief's own
  model, comes out at about +14 to +15% for a gradient run [e]: the forward pays the
  rows, the steps and the 530 discarded attempts (3180 evaluations, about +11% of
  28 716), and the sweep pays the rows. So B meets R3 in rows and sits on the line in
  time. If the bar is time, the cheapest lever is the measured one: no cut where the
  attempt is under 0.25 d. S2 found 243 of the 530 cuts there, buying nothing
  measurable [m]. Its nudge is unmeasured, between 0.0020 and 0.0081 [e, bracketed
  by the 0 d and 0.5 d runs]; the 0.5 d rule's 0.0081 fails R1.
- *R1 and R3 were measured with knot pulses.* Without them (the account deletes
  them), steps across a cluster are longer, so the cuts are worth more and cost more.
  Neither is measured. Dropping the pulses alone gives rows ×0.758 on dry [m,
  `localised.md`, libS, a09, 1e-4], so the budget gains room. That is not credited
  to B.
- *R2.* B holds the row ends at θ₀'s zeros. Per crossing of a stage by one node's
  zero the jump is b_i · w_node, where w_node ≈ (θ/J/ε)·λ_soil·h·ΔG / 51. Taking the
  largest window's cluster at about 0.6ε (−0.062ε at φ about 0.1 [m, part 4]) gives
  w_node about 0.012ε, so a jump of at most 0.4 × 0.012 ≈ 0.005ε in a 2-d step, and
  about 0.001ε inside the 0.44-d bracket [e]. Both pass the bar as challenged
  (per jump). A holds the bracket at θ′ but leaves the 49 interior zeros crossing the
  middle piece's stages just as B does. So A's R2 advantage is the radius, not
  smoothness. This was found here, and it is why A is not the winner.
- *J kinds in B.* A J declared `ends_step` would put a held row end on a rate jump.
  At θ₀ the jump sits on the first stage of the next row (weight 37/378), so the
  pinned map is discontinuous there and central differences fail R6. B therefore
  cannot accept a J. That is a domain limit, written into *What this makes hard*,
  not a hidden one.

## What survives deletion

Each name, and the ledger line that breaks without it:
- **`sign_aux{int aux; bool ends_step;}`** (plant, strategy): R4. Without it each
  point is a member and a Patch loop (the floor).
- **`ends_step`**: R5 and R1. Without it the Patch cannot route a zero to the step
  or to the node. Routing f_hi to the node split gives 0.044 [m]: R1 fails.
- **`std::vector<sign_aux> sign_auxes() const`** replaces `sign_value_aux()`: R4. It
  is a rename plus a list, not a new name.
- **`SplitsSignChanges` gains `step_end(step, last, u) -> bool`** (odelia concept,
  Patch implements): R1. odelia owns where a step ends, and only the System can find
  the zero, because only it holds the field. Shape and coupling bool as
  `split_sign_changes`.
- **`SolverInternal::ended_at_first_`**: R1. The bracket's second end is what was
  measured (E6, S2 [m]); a cut at the first zero alone leaves the cluster inside the
  next step.
- **`step_outcomes::cut_at_sign_change`**: R3, which asks for evaluations, and the
  existing guarantee that `attempts()` is the sum of the outcomes. The JT build's cut
  attempt was counted nowhere [m, from its diff], which drops that guarantee.
- **`sign_change::value`** (which of the System's sign values a node's zero
  belongs to): R4 for a second point of node reach. Without it the split has to
  refuse a second node-reach entry. It is one field and about three lines.
- **phylloptim's `arm_margin_dry_`** (f_hi kept on the leaf, NaN where no collar
  solve ran), with plant's aux of the same name: R1. It is the point's own
  definition.

Removed by the pass:
- A's `piece` record and the active `taken_step::h`: no line with a number pays.
- C's every-row field samples: no line with a number pays.
- A per-stop record field: rows are rows, and a held stop is a row end, so storing it
  again stores what is derived.
- A separate list of knots on the row: they are among `subsystem_substeps::ends` and
  derivable from the driver.
- An enum for reach (`node`/`patch`): two values that are a yes/no question about the
  step.
- A "minimum attempt for a cut" knob: not demanded until R3 is read as time (see
  the consistency pass).

## What this settles

- No new record type, and no change to `step_record`, `solved_row`, `instruction`,
  `subsystem_substeps` or `split_block` (beyond `sign_change::value`). The leaf
  switch's stops are ordinary rows.
- `step_by`, `step_to`, `advance_recorded`, `solve_adjoint` and `step_adjoint` are
  unchanged for the leaf switch. Replays, walks and the sweep do nothing new.
- A new point of either reach is one list entry. Patch code is generic over the
  list, so no second `stop_value_aux` can be written.
- The knots have one account: the soil's substeps. The harness's 2951 zero-depth
  pulses on dry go, and with them the identity insertion rows (19.6% of the sweep at
  u108 [m]) and their rows (×0.758 on dry [m]). Gate as `localised.md` did: largest
  move 0.23ε [m].
- TF24f opts out with an empty list instead of a deleted member.
- An invader's leaf switch is not a stop. Its range is the soil, which a walk does
  not integrate; this follows from the range, with no exception written.

## What this makes hard

- *J kinds (#13, #14, #19).* A held row end on a rate jump makes the pinned map
  discontinuous at θ₀. If one appears on accepted stages, cope by declaring nothing
  for it, so it stays inside a step as today, and hand off to A.
- *A grid's radius in θ.* At θ′ the held ends no longer bracket the cluster once the
  zeros move by about its width (0.44 d [m]). The error then grows toward the
  unbracketed one, up to |Σc| 0.18ε in one run [m, part 4]: still within ε, but no
  longer reproducible. Cope: a pinned replay can run `step_end`'s search without
  acting and report the largest distance from a held end to its zero. That is the
  diagnostic OBJECTIVES asks for, at about one search per cut row. Rebuild the grid
  past it.
- *A cluster spread over several steps.* Each step brackets only its own zeros,
  first then last. Measured fine on dry (33 in-and-out pairs, no chatter [m]);
  episodic and long drought are unmeasured.
- *A point whose reach is the soil but not every node.* `ends_step` is all or
  nothing. A narrower reach would need a range in place of the bool; no witness has
  one.
- *Invaders' own corners off the diagonal.* They are still held at the run's zeros,
  as today. Cope: C.
- *A harvest at a band edge* is a jump of the map in θ (height against a bound at a
  known time), not a division of time. It is outside every candidate.

## Kill condition

- *R2's radius fails.* The f_hi zeros move by more than the cluster's width over
  the ±10% resident radius (measure: zero times at θ₀ and θ₀ ± 10% along the trait
  that moves them most, on dry). Hand off to **A**, which keeps the bracket on the
  zeros at θ′.
- *R9 answers "often".* A J kind is met on accepted stages on the bank. Hand off to
  **A**: a moving piece boundary carries the jump's term.
- *Invader chords jump.* Hand off to **C**.
- *R3 is read as time and B's +14–15% [e] is over.* Add the measured minimum-attempt
  rule; do not change the design.

## The design

### The declaration (plant, strategy) — the one data structure the witnesses share

```cpp
// An auxiliary at whose zero the rates change form. Where the zero moves only the
// node's own rates the node is integrated in pieces; where it moves the soil,
// which every node reads, the step ends there.
struct sign_aux {
  int aux;
  bool ends_step;
};

// TF24_Strategy
// Net production, which storage reads through its smooth positive part, and the
// leaf's marginal profit at the dry end, whose zero puts uptake on the bound.
std::vector<sign_aux> sign_auxes() const {
  return {{aux_idx_net_mass_production_dt, false},
          {aux_idx_arm_margin_dry, true}};
}
```

`NamesSignValue<T>` becomes `NamesSignValues<T>` (requires `sign_auxes()`).
TF24f's `sign_value_aux() = delete` becomes an empty list. phylloptim keeps f_hi
(`arm_margin_dry_`) on each collar solve, NaN where no collar solve ran. That is
JT's member, reset per solve and per replay.

### odelia: one field and one concept member

```cpp
// fraction u of the step, the slope in u there, and what the evaluation at u solved
// for.
template <class Values>
struct sign_change {
  std::size_t value = 0;
  double u = 0.0;
  double slope = 0.0;

```

```cpp
// SplitsSignChanges gains:
//   Where the step just taken must end: the first zero of a sign value that ends
//   steps, or the last where `last`, as a fraction; 1 where none lies inside.
//   True where it evaluated anything, which moves the System off the step's end.

```

```cpp

  // steps, so the next ends at the last zero in its span.

// step_outcomes
```

In `SolverInternal::step`, after the error estimate keeps the attempt and before

```cpp
if constexpr (SplitsSignChanges<System>) {
  if (method == Method::rkck && !cut) {
    double u = 1.0;
    if (system.step_end(stepper.taken(time, step_size, dydt_out, y,
                                      sign_values_in),

      stepper.read_end_sign_values(system);

      ++outcomes_.cut_at_sign_change;
      y = y_orig;
      time = time_orig;
      step_size *= u;
      cut = true;
      continue;
    }
  }
}
// on acceptance:
ended_at_first_ = cut && !ended_at_first_;
```

### plant: Patch, generic over the list

- `sign_values(out)`: for each listed aux, then each node, so a value's index is
  `a * nodes + node`. The Step already keeps them at the start, the five stages and
  the end.
- `split_sign_changes`: for each node, `step.sign_changes` on each of its
  `!ends_step` values; the changes merged by u, each tagged with `value`. One
  `split_block` per node, as today.
- `split_as_recorded`: the residual reads `change.value`'s aux, through
  `node_rates_in_field` returning the aux it is handed.
- `take_recorded_splits`: copies `value`.
- `step_end(step, last, u)`: `step.sign_changes` on each `ends_step` value of each
  node, on `node_value_at` (that node's rates in the sampled field). It returns the
  least, or the greatest, zero in (0, 1). This is JT's `stop_fraction` without its
  scans and logs, sharing `sample_field` and `node_value_at`.

2. `step_end(taken, ended_at_first_ = false, u)`. Patch reads the f_hi block's six

3. The attempt is retaken to u·h and error-tested. The P split runs on the retaken

4. The next step starts at the first zero. `step_end(..., last = true)` returns the

5. The third step is free.
